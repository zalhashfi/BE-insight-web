# 🤖 AGENT.md — Operational Guide for BE-insight-web

_This file is the single source of truth for autonomous agents (and humans) operating on this repository._

## 1. What This Project Is
`BE-insight-web` is an **Express.js (Node.js)** REST API backend for an IoT environmental monitoring system (AQMS = Air Quality, SOC = Soil/Water Quality). It receives telemetry from ESP32 devices, stores raw + processed data, serves data to a dashboard, and manages OTA firmware updates.

**Stack**: Node.js + Express + TypeScript (via `tsx`), Pure MySQL (via `mysql2/promise` connection pool). **No ORM.**

## 2. Hard Conventions (Do Not Violate)
- **Pure SQL only**: Use `query(sql, params)` from `src/db/pool.js`. Never use an ORM. Always parameterize (`?` placeholders) to prevent SQL injection.
- **Express `Router()`**: All routes use `express.Router()`. No Hono, no Cloudflare Workers, no `c.req`/`c.json` syntax.
- **File extensions in imports**: ESM is enforced (`"type": "module"`). Relative imports MUST end with `.js` (e.g. `import { x } from './db/pool.js'`).
- **Manual UUID**: `uuid` for a device is supplied by the caller in the request body, NOT auto-generated by the server.
- **Soft deletes only**: Deleting a device sets `is_deleted = TRUE`. Never `DELETE FROM device`.
- **Dual-path storage**: Every ingest writes to `raw_data_log` (cold) AND to `aqms_reading`/`soc_reading` (hot) based on `device.type`.

## 3. Project Layout
```
src/
  index.ts            # App entry: mounts all routers, global middleware, error handler
  db/
    pool.ts           # mysql2 connection pool + query() helper
    schema.sql        # Full CREATE TABLE statements (run via npm run db:init)
    init.ts           # Runner that executes schema.sql
  middleware/
    auth.ts           # authenticateJWT, requireAdmin
  routes/
    iot.ts            # /api/iot/* (identity, ingest, ota) — device-facing
    auth.ts           # /api/auth/* (register, login, me) — dashboard user auth
    data.ts           # GET /api/devices/:uuid/data/:sensorType
    devices.ts        # /api/devices/* (CRUD, unregistered list)
    firmware.ts       # /api/firmware/* (list, create, latest)
```

## 4. Common Commands
```bash
npm install           # Install deps
npm run dev           # tsx watch src/index.ts (hot reload, dev)
npm run build         # tsc -> dist/
npm start             # node dist/index.js (production)
npm run db:init       # Create tables from src/db/schema.sql
```

## 5. Environment Variables (`.env`)
`PORT`, `NODE_ENV`, `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_PORT`, `JWT_SECRET`, `IOT_DEVICE_SECRET`.

## 6. Deployment Target
Hostinger Shared/Cloud Hosting (Node.js app). See `HOSTINGER_DEPLOYMENT.md`. Startup file: `dist/index.js`.

## 7. Gotchas for Agents
- `src/middleware/auth.ts` exports `AuthRequest` (extends Express `Request` with `user`). Use it for typed handlers.
- `x-api-key` header = device `uuid`. `x-device-secret` header = `IOT_DEVICE_SECRET` (for `/identity` only).
- Dashboard routes expect `Authorization: Bearer <jwt>` from `/api/auth/login`.
- Never import from `../db/pool` without the `.js` extension — it will fail at runtime under NodeNext ESM.
